# v1.10 合格信息机制：构造、完整结果与边界

本扩展已经完成：一个不放宽 global 0.010 AUC 门槛、保留三个候选且 `I(Y;D|S,C)>0` 的有限支持构造；同一构造提供 10% 正 oracle 收益与 20% 零 oracle 收益；300 次独立标签重复及单独的有限验证筛选诊断。原 v1.9 情景、原始数据、历史候选重建及真实数据主 24 对比均未修改。

## 1. 数学构造及候选资格

四个 score 组质量为 (0.6, 0.2, 0.1, 0.1)，S=(0.040, 0.080, 0.110, 0.112)。各组 U=−1/+1 各占一半。令 q=P(Y=1|S,U)=S+0.0025U，D=0.0004+0.0002U，候选为 (S−D/2, S, S+D/2)，固定部署阈值 τ=0.100。总阳性率 0.0622。

三个候选均值 C=S，因此 W=(S,C) 不识别 U，而 D 识别 U。故 q_W=S，q_WD=q。由 Bernoulli KL 恒等式，I(Y;D|W)=Σ mass×KL(Ber(q)||Ber(S))=0.00006368641625794 nats>0。这是既有条件信息/决策理论的实例，不声称新定理原创。

| 候选 | 总体 AUC | 与全局最优 AUC 差 | 总体 Brier | 通过原 0.010 门槛 |
|---|---:|---:|---:|---|
| lower | 0.620475917160 | 0.009000335327 | 0.05749615 | 是 |
| center | 0.624976084823 | 0.004500167663 | 0.05749560 | 是 |
| upper | 0.629476252487 | 0.000000000000 | 0.05749515 | 是 |

最大 AUC 差 0.009000335326779<0.010；即使不使用程序的 1e−6 数值容差也通过。三候选 Brier 也非常接近，最大值远小于 1.10×全局最小 Brier。D 的幅度小并不自动保证 AUC 相近，因为同 S 内的排名方向决定 AUC；本构造实际算得差值满足门槛。具体地，外侧候选 AUC 差为 αΣm_g²/[2π(1−π)]，其中 α=0.0025、Σm_g²=0.42、π=0.0622，中间候选 AUC 是两者平均。

该设计是在已知旧 B/C/D 资格失败后作的解析构造，不是事前注册。第一次确定性可行性核算即使用这里的参数；未依据随机拟合收益挑参数。一个非生产 seed=1100192 的实现 smoke test 只检查恒等式；冻结后未改变设计或按结果删除 seed。

## 3. 冻结重复协议与有限拟合

- 种子261020000–261020299，300个全部保留；支持质量与候选预测固定。
- 两种独立训练标签样本量8,000与80,000；独立验证10,000、独立评价10,000。SeedSequence([seed,110]).spawn(5) 分别生成两训练流、验证流、评价流与队列并列排序流。两个训练样本量共用当次评价标签及排序，便于配对。
- 对每个信息集使用相同 saturated Beta(1/2,1/2) 或 additive logistic 学习器；ridge=1e−6，maxiter=500，无随机结果调参。主拟合固定总体合格的三候选集合。
- Pos/FN/FP/AllErr 与 5/10/15/20% 均冻结。主展示为 Pos10%、8,000训练；其他目标及80,000训练是预列比较。记录57,600条队列记录、28,800条配对记录、300条独立验证记录。

## 4. 独立有限验证筛选：必须重算实际 consensus

验证诊断按每次实际global最优AUC−0.010（仅1e−6数值容差）选择候选。该诊断只执行 AUC 门槛，未把总体合法性当作有限验证必过；它不是对筛选后集合重新拟合审核学习器。对实际保留集合重新计算 C 和 D，精确枚举其 oracle 条件信息及 Pos10%预算效应。

| 事件 | 次数 | 比例 | MCSE（比例尺度） |
|---|---:|---:|---:|
| M_1 | 29/300 | 9.67% | 0.017061 |
| M_2 | 100/300 | 33.33% | 0.027217 |
| M_3 | 171/300 | 57.00% | 0.028583 |
| range_valid | 271/300 | 90.33% | 0.017061 |
| positive_conditional_information | 171/300 | 57.00% | 0.028583 |
| positive_oracle_boundary_gain | 171/300 | 57.00% | 0.028583 |

M=2实际均为相邻候选对；C=S±D/4 已识别 U，故在W=(S,C)后加入D的条件信息和oracle增益均为0。不能把三候选时C=S的结论沿用。理论上仅保留两外侧候选会仍有信息，但本门槛不可能产生该集合：center AUC恒为两外侧AUC平均，若两外侧都通过，center也必通过。M=1为零range；M=3的171次才保留正条件信息与正10%oracle边界效应。因此有效range的90.33%不等于有新增信息的57%。

这些频率只描述本设计固定验证样本量下的标签随机性，不是普适筛选成功率。主拟合结果固定三个总体合格候选，与本段筛选诊断分开。

## 5. 数值失败、完整重跑及显式修正链

首轮在seed261020109的W、80,000训练 additive 拟合遭原 L-BFGS-B 异常停止，尚无Monte Carlo结果CSV。`failed_run_01.json`及`initial_frozen_source.py`/`initial_frozen_tests.py`保留该状态。没有采用已完成前缀的截断均值。

首个显式 amendment 保持统计设计、所有seed、样本、目标函数、ridge与maxiter，原求解失败时仅增加maxls=100，并以BFGS交叉核同一目标：两个梯度∞范数≤1e−7，目标差≤1e−10，预测差≤1e−6。随后从头完整重跑300次。实际仅3个恢复（261020109/183/193的W、80,000训练）；最大梯度1.1122e−9，最大BFGS梯度3.1434e−10，最大目标差2.7756e−17，最大预测差1.3836e−9。所有实际记录均有限。

完成后第二个显式 amendment 增加对两解、目标、梯度与差值的finite fail-closed校验，以及图件布局/标签；未更改任何实际CSV或重跑生产。最终第三个presentation-only amendment使C面板两行均值注释的白底明确不透明、padding=1.5、zorder=10，防止参考线穿过文字；仅重绘三格式图，原9个CSV哈希再次核对不变。当前10项tests通过，含失败seed重放及非有限参考解拒绝测试。`production_source.py`/`production_tests.py`保存生产时实现；`source_amendments_at_production.json`精确保留run_manifest中记录的旧amendment文件哈希。当前`source_amendments.json`记录后续实现与展示更改，不伪称当前源码就是首次冻结或生产源码。

已完成独立复核：两位只读审查者分别重算总体AUC/Brier/KL与16个target×budget oracle结果，检查实际保留集合信息；三生产seed重放及完整聚合核对通过；全部生产9个CSV、原protocol与历史依赖哈希保持一致。最终以仓库相应审查报告为准，不把这些检查称为新的实证证据。

## 7. 复现入口及哈希

当前生产目录拒绝覆盖。可以直接运行`.venv/bin/python -m pytest tests/test_mechanism_v1_10.py -q`核验10项；`.venv/bin/python src/mechanism_v1_10.py figures`只重绘且先检查数值CSV哈希。确定性表用`design`子命令。完整独立重放应指向新空目录，保留原生产目录，例如：

```python
from pathlib import Path
import tempfile, shutil, json
from src import mechanism_v1_10 as m
production=m.OUT
expected=json.loads((production/'run_manifest.json').read_text())['outputs']
replay=Path(tempfile.mkdtemp(prefix='kbs-qualified-replay-'))
for name in ('protocol.json','source_amendments.json'):
    shutil.copy2(production/name,replay/name)
m.OUT=replay
m.run()
assert all(m.digest(replay/name)==h for name,h in expected.items())
print(replay)
```

该入口不覆盖旧结果；不同平台求解器/浮点库的逐字节重放需结合记录环境检查，不应把平台差异静默当作一致。原生产环境见run_manifest。
